# n8n Workflow Setup Guide — Google Review Reputation System
# ============================================================
# Two workflows: MAIN (event-driven) + REPORT (scheduled)
# Estimated setup time: 90 minutes
# n8n version tested: 1.x (Cloud or Self-Hosted)
# ============================================================


# ─────────────────────────────────────────────────────────────
# PRE-FLIGHT: CREDENTIALS TO CREATE FIRST
# ─────────────────────────────────────────────────────────────

Before building any nodes, create these credentials in
n8n → Settings → Credentials:

1. GROQ API
   Type: Header Auth
   Name: Groq API
   Header Name: Authorization
   Header Value: Bearer <your-groq-api-key>
   (Get key from: console.groq.com)

2. GMAIL
   Type: Google OAuth2
   Name: Gmail Account
   Follow n8n's Google OAuth2 guide. Scopes needed:
   https://www.googleapis.com/auth/gmail.send

3. MICROSOFT 365 (for Excel Online)
   Type: Microsoft OAuth2
   Name: MS365 Account
   Follow n8n's Microsoft OAuth2 guide. Scopes:
   Files.ReadWrite, Files.ReadWrite.All

# NODE 1 — Webhook Trigger
# ─────────────────────────────────────────────────────────────
Type: Webhook
Name: New Review Received

CONFIGURATION:
  HTTP Method:      POST
  Path:             new-review
  Authentication:   None (or Header Auth for production)
  Response Mode:    Immediately
  Response Code:    200
  Response Body:    {"status": "received"}

After saving, copy the Production Webhook URL.
Paste it into your Python scraper's .env as N8N_WEBHOOK_URL.

TEST:

  Send a test POST with a sample payload from the scraper.
  Confirm the node shows green and the data appears in Output.


# ─────────────────────────────────────────────────────────────
# NODE 2 — HTTP Request to Groq
# ─────────────────────────────────────────────────────────────
Type: HTTP Request
Name: Analyze Review (Groq)

CONFIGURATION:
  Method:           POST
  URL:              https://api.groq.com/openai/v1/chat/completions
  Authentication:   Predefined Credential Type → Header Auth → "Groq API"

  Send Headers:     ON
    Content-Type:   application/json

  Send Body:        ON
  Body Type:        JSON

  Body (paste exactly, the expressions pull from Node 1 output):
  {
    "model": "llama-3-70b-8192",
    "temperature": 0,
    "max_tokens": 300,
    "response_format": { "type": "json_object" },
    "messages": [
      {
        "role": "system",
        "content": "<PASTE ENTIRE CONTENTS OF groq_system_prompt.txt HERE>"
      },
      {
        "role": "user",
        "content": "Stars: {{ $json[\"Rating\"] }}\nReview: {{ $json[\"Review\"] }}"
      }
    ]
  }

  NOTE: In the JSON body editor, switch to "Expression" mode for the
  user content field so the {{ }} expressions are evaluated.
  temperature: 0 is critical — eliminates randomness in JSON output.

TIMEOUT: 30 seconds


# ─────────────────────────────────────────────────────────────
# NODE 3 — Code Node: Parse Groq Response + Merge Fields
# ─────────────────────────────────────────────────────────────
Type: Code
Name: Parse LLM Output
Language: JavaScript

CODE:
// Pull the raw LLM JSON string from Groq's response
const groqResponse = $input.item.json.choices[0].message.content;

// Parse it — Groq with json_object mode should always be valid JSON
let llm;
try {
  llm = JSON.parse(groqResponse);
} catch (e) {
  // Fallback if Groq somehow returns malformed JSON
  llm = {
    sentiment: "NEGATIVE",
    agent_name: "N/A",
    complaint_category: "Other",
    details_provided: false,
    reason_for_review: "parse error",
    review_status: "Negative"
  };
}

// Pull the original scraper payload from Node 1 (two nodes back)
// In n8n you reference previous nodes by name:
const original = $('New Review Received').item.json;

// Merge scraper fields with LLM fields into one flat object
// This is the final shape that all downstream nodes consume
return {
  json: {
    // ── Scraper fields ──────────────────────────────────────
    review_id:                      original.review_id,
    "Review Date":                  original["Review Date"],
    Department:                     original.Department,
    Rating:                         original.Rating,
    Review:                         original.Review,
    "Customer Name in Google":      original["Customer Name in Google"],
    Branch:                         original.Branch,
    Day:                            original.Day,
    Month:                          original.Month,
    Year:                           original.Year,

    // ── LLM fields ──────────────────────────────────────────
    "Reason for Review":            llm.reason_for_review   || "",
    "Agent Name":                   llm.agent_name          || "N/A",
    "Review Status":                llm.review_status       || "",

    // ── Routing flags (used by IF nodes, not written to Excel) ──
    sentiment:                      llm.sentiment,
    complaint_category:             llm.complaint_category  || "Other",
    details_provided:               llm.details_provided    === true,

    // ── Action columns (blank until reply is sent) ───────────
    "Latest Action Taken To Customer": "",
    "Latest Action Date - Customer":   "",
    "Latest Action Date - Internal":   "",
    "Complaint Resolution Days":       "",
  }
};

# NODE 5a — Code Node: Pick Reply Draft
# ─────────────────────────────────────────────────────────────
Type: Code
Name: Select Positive Reply Draft
Language: JavaScript

CODE:
// Three pre-drafted positive reply templates.
// Rotate by day of week so replies feel varied, not templated.
const POSITIVE_REPLIES = [
  // Template A — warm and personal
  `Thank you so much for your kind words! We're thrilled to hear about your positive experience with us. Our team works hard every day to provide the best service possible, and feedback like yours truly makes a difference. We look forward to serving you again!`,

  // Template B — concise and professional
  `Thank you for taking the time to share your experience! We're delighted you were satisfied with our service. Your feedback motivates our entire team. We appreciate your trust and look forward to continuing to serve you.`,

  // Template C — agent-focused (best when agent_name is present)
  `We're so glad to hear you had a great experience! Our team is dedicated to making every interaction as smooth and helpful as possible. Thank you for your kind review — it means the world to us. We hope to see you again soon!`
];

// If an agent was named, prefer Template C
const agentNamed = $json["Agent Name"] && $json["Agent Name"] !== "N/A";
let templateIndex;
if (agentNamed) {
  templateIndex = 2;
} else {
  // Rotate A/B based on the day number (creates variety without randomness)
  templateIndex = parseInt($json.Day || "1") % 2;
}

return {
  json: {
    ...$json,
    selected_reply: POSITIVE_REPLIES[templateIndex],
    template_index: templateIndex + 1,
  }
};

# NODE 7a — Wait Node: Pause for Approval Click
# ─────────────────────────────────────────────────────────────
Type: Wait
Name: Wait for Approval

CONFIGURATION:
  Resume On:       Webhook
  Webhook Suffix:  (leave blank — n8n auto-generates per execution)
  Limit Wait Time: ON
  Time:            24 Hours

HOW IT WORKS:
  The Wait node pauses execution and gives you a unique
  $execution.resumeUrl for this specific workflow run.
  That URL was embedded in the APPROVE and REJECT buttons
  in Node 6a's email.

  When you click APPROVE → the URL is called with ?approve=yes
  When you click REJECT  → the URL is called with ?approve=no
  The workflow resumes from this node with those query params available.

// Complaint-category-aware detailed apology drafts
const DETAILED_DRAFTS = {
  "Total Loss Handling":
    `Dear {{ $json["Customer Name in Google"] }}, we sincerely apologize for the delays and lack of communication you've experienced with your total loss claim. This is not the standard of service we hold ourselves to. We are escalating your case immediately and a senior claims manager will contact you within 24 hours to resolve this personally.`,

  "Wait Time / Delays":
    `Dear {{ $json["Customer Name in Google"] }}, we're truly sorry for the unacceptable wait times you experienced. Your time is valuable, and we failed to respect that. We are reviewing our processes to prevent this from happening again, and we'd love the opportunity to make this right for you.`,

  "Staff Attitude":
    `Dear {{ $json["Customer Name in Google"] }}, we are deeply sorry to hear about your experience with our team. The behavior you described does not reflect our values or the standard of care we demand. This has been escalated to our management team for immediate review.`,

  "Claim Processing":
    `Dear {{ $json["Customer Name in Google"] }}, we sincerely apologize for the difficulties you encountered during your claim. We understand how stressful this process can be, and we clearly fell short of your expectations. We'd like to personally review your case — please allow us to reach out directly.`,

  "Communication Failure":
    `Dear {{ $json["Customer Name in Google"] }}, we're truly sorry for the breakdown in communication you experienced. Keeping our clients informed is a core responsibility, and we let you down. We're taking immediate steps to follow up on your case and improve our communication processes.`,

# EXCEL SETUP — Do this before running the workflow
# ─────────────────────────────────────────────────────────────

1. Open your Excel Online workbook.
2. In the first row, create these exact headers (copy-paste):

   Review Date (dd/mm/yyyy) | Department | Rating | Review | Customer Name in Google | Reason for Review | Agent Name | Latest Action Taken To Customer | Latest Action Date - Customer | Latest Action Date - Internal | Complaint Resolution Days | Review Status | Branch | Day | Month | Year

3. Select ALL header cells + at least 1 blank row below.
4. Go to: Insert → Table → "My table has headers" → OK
5. In the Table Design tab, rename the table to: ReviewsTable
6. Save the workbook. Note the exact file path in OneDrive/SharePoint.

WHY A NAMED TABLE:
   n8n's Excel 365 node requires a named Excel Table (not just a range)
   to append rows reliably. Without it, the API write fails silently.
