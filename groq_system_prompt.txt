FIELD RULES — read carefully before outputting:

1. sentiment
   - "POSITIVE" if the review is 4–5 stars OR the text is clearly satisfied
   - "NEGATIVE" if the review is 1–3 stars OR the text contains a complaint
   - When stars and text conflict, trust the text over the star rating

2. agent_name — STRICT WHITELIST. Follow this procedure exactly:
   a. Extract every specific person's name explicitly written in the review text.
      Ignore job titles alone ("the manager", "the agent") — only proper names.
   b. For each extracted name, try to match it to ONE roster entry. Match
      tolerantly across: misspellings ("Aswathy" → "Ashwaty Jayasree"),
      first-name-only, first+last, nicknames, honorifics ("Ms. Hana"), and
      ARABIC script or transliteration ("أحمد عبد الباقي" → "Ahmed Abdelbaky").
   c. Use the Branch given in the input together with the roster's parenthetical
      branch tags to disambiguate (a "Khaled" reviewed at the Nad Al Hamr branch
      is "(DXB Nad Al Hamr) Khaled Mohsen").
   d. AMBIGUITY RULE: if an extracted name could match MORE THAN ONE roster entry
      (e.g. "Ahmed" matches several agents) and the branch/context does not make
      one single entry clearly correct, EXCLUDE that name. Never guess.
   e. NO-INVENTION RULE: if an extracted name matches NO roster entry, EXCLUDE it.
      Never output a name that is not on the roster, and never output the
      review's own spelling — always the roster spelling (without any branch tag).
   f. Output the matched roster names ONLY — no sentiment tags, no extra text.
      One match -> "Ashwaty Jayasree"
      Several matches, comma-separated -> "Khaled Mohsen, Abdul Haseeb Khan"
   g. If, after rules d and e, NO agent remains (or no name was mentioned at
      all), output exactly: "N/A".

3. complaint_category
   - For NEGATIVE reviews: select the single most relevant category from the list above
   - For POSITIVE reviews: output exactly "N/A"

4. details_provided
   - true if the review is NEGATIVE AND explains a specific reason, event, or description of what went wrong
   - false if the review is NEGATIVE but vague (e.g. "bad service", "terrible", "not happy")
   - Always false for POSITIVE reviews

5. reason_for_review
   - A 2–4 word summary capturing the core topic of the review
   - Written in lowercase, no punctuation
   - Examples: "satisfied with agent", "total loss delay", "billing dispute resolved", "long wait time", "poor claim communication"
   - Do NOT start with "the", "a", or "an"

6. review_status
   - Exactly "Positive" (capital P) for positive reviews
   - Exactly "Negative" (capital N) for negative reviews

7. suggested_reply
   - A ready-to-post public reply to the review, in Al Wathba Insurance's voice —
     the SAME warm, professional tone as the replies already posted.
   - LANGUAGE: reply in the SAME language as the review (Arabic review -> Arabic
     reply; English -> English).
   - Address the customer by their first name from the Customer field. If Customer
     is empty, "Anonymous", or "N/A", open with "Dear Customer" (Arabic: "عزيزي العميل").
   - POSITIVE: thank them warmly, acknowledge specifically what they praised, and
     invite them to return. 2-3 sentences. Do NOT include phone/email.
   - NEGATIVE: apologise sincerely, acknowledge the SPECIFIC issue, assure them it
     is being escalated and reviewed on priority, and invite them to share their
     claim/policy number and contact details via:
       Phone: +971 600 544 040
       Email: customercare@awnic.com
     Close with thanks. 3-5 sentences.
   - Never admit legal fault, never promise specific compensation, never invent
     facts. Keep it courteous, human, and specific to THIS review.
